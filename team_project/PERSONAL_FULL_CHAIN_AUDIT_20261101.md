# 개인 자율주행·사람 시뮬레이션 전체 연결 점검

기준: 2026-11-01, ROS 2 Jazzy / Gazebo / WSL. 팀 원본 매핑·주행 패키지와 Robot 02 Nav2 설정은 보존. 개인 실행·안전 보조·시험 도구 범위에서 수정했다.

## 판정

기존 검토된 LiDAR 지도에서 배달·적재·회수·HOME 복귀와 사람 대응은 실제 시뮬레이션으로 연결 확인했다. 새 자동 탐색 지도는 아직 완성되지 않았으므로, 새 지도 생성부터 서빙까지 하나의 연속 시험이 통과했다고 판단하지 않는다. 단계별 시험과 지도 인계 검사를 수행했다.

## 이번에 수정한 문제

1. 수동 매핑 도구 `scan_site_map.py`가 TEAM 자동 매핑 중에도 직접 cmd_vel을 발행할 수 있었다. 자동 매핑 역할에서는 실행을 거절하도록 수정하고 실제 거절을 확인했다.
2. 매핑 세션의 odom 준비 조건이 최초 수신 뒤 신선도를 검사하지 않았다. 마지막 수신 시각 1초 조건을 추가하고, 금지된 사람 처리 노드 검사 및 탐색/정리 전체 제한 시간도 보완했다.
3. TEAM 매핑 브리지가 /clock을 약 958~998Hz로 발행했다. 개인 매핑 launch에서 해당 브리지의 시계 출력만 /mapping/raw_clock으로 분리하고 기존 개인 100Hz 시계 릴레이를 재사용했다. 물리 시뮬레이션 step과 시각 값은 바꾸지 않았다.
4. 시계 릴레이의 Best Effort 발행과 TEAM 준비 확인기의 Reliable 구독이 호환되지 않아 시작이 대기했다. 개인 릴레이를 Reliable로 변경해 준비 확인과 SLAM/Nav2 활성화를 재검증했다. /clock 발행자는 한 개다.
5. 새 지도를 선택해도 목적지와 초기 위치 주변의 알려진 자유 공간을 시작 전에 검사하지 않았다. `site_map_checks.py`와 운행 시작 검사를 추가했다. 로봇 몸체 반경, 미확인 영역, 이미지 경계, 회전된 원점, raw/trinary/scale 형식을 반영한다. 테이블은 적어도 한 접근점이 유효해야 한다. 이 검사는 지도 전체 완성도나 경로 연결성을 대신하지 않는다.
6. 사람 시험에서 잘못된 복도 시작 프로필을 선택한 시험 구성 오류를 재현했다. 사람은 생성됐으나 뒤쪽에 있어 고정 전방 차단 시나리오가 성립하지 않았다. 시험 도구가 다른 프로필을 거절하도록 추가하고 올바른 validation_cafe 프로필로 재시험했다. 인식 기준을 낮추지 않았다.

## 남아 있는 매핑 문제

자동 탐색은 실제 Nav2 이동과 지도 저장을 수행했지만, map→odom TF가 0.5초 이상 늦는 구간에서 안전 취소·회복이 반복된다. 100Hz 시계 변경 후 odom→base가 신선해도 map→odom 지연은 남았다. 따라서 시계 발행량을 단독 원인으로 결론내리지 않는다. 안전 임계값 완화나 TF 재타임스탬프로 지연을 숨기지 않았다.

SLAM Toolbox는 기본적으로 스캔 시각을 TF 시각에 사용한다. 이 동작은 [공식 설명](https://github.com/SteveMacenski/slam_toolbox/issues/717)과 [공식 파라미터 문서](https://github.com/SteveMacenski/slam_toolbox#toolbox-params)에서도 확인된다. 다음 원인 분석은 처리된 스캔 시각·SLAM 계산 지연·실제 TF 발행 간격을 함께 계측해야 한다.

수정 후 90초 탐색: 3.301m 최대 odom 변위, 지도 업데이트 58회, 지도 저장 성공, map_complete=false. 증거: `maps/drafts/demo_lidar_complete_final_20261101_000337/personal_mapping_role.json`. 그 이전 비교 실행은 수정 적용을 위해 OPERATOR_INTERRUPTED로 종료했으며 결과를 보존했다.

초안 지도에는 주방 또는 일부 테이블 접근점의 알려진 몸체 여유 공간이 부족했다. `_local_only/map_handoff_audit_20261101.json`에 비교값을 기록했다. 기존 운행용 지도의 YAML/PGM 해시는 변하지 않았다. 부분 지도를 완성 지도처럼 적용하거나 원래 지도를 덮어쓰지 않았다.

`_local_only/corridor_trial_20261101_002133.json`: 성공, 오류 없음. 수동 통로 등록 없이 `map_corridor_1` 추출, Robot 02 선도착 우선권(FIRST_ARRIVAL)과 실제 진입 순서 02→01 일치. 주문 수신 번호는 Robot 01=3, Robot 02=4였지만 선도착 Robot 02가 우선했다. 두 주문 완료, 실제 최소 중심 간격 1.313990m, 접촉 없음.

시험 런타임은 stop_autonomy.sh로 종료했고 runtime.json 제거 및 소유 Gazebo/Explorer 잔류 여부를 확인했다. 다음 기본 실행은 system.yaml의 기존 demo_lidar_operation 프로필을 사용한다. 시험용 장소 선택은 기본 설정을 변경하지 않았다.

결론: 개인 서빙·사람·교행 체인은 이번 재시험에서 통과했다. 새 자동 매핑 지도의 전체 완성·목적지 인계는 미통과이며, 이를 해결했다고 보고하지 않는다.
