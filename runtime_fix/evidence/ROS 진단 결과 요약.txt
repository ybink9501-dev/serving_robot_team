| 구성 | 실제 확인된 근거 | 현재 판정 |

| 지도→로봇 TF | `(-3.191, -2.234)`, 약 -0.431° 출력 | 연결 성공 |
| Nav2 | 네 Lifecycle 노드 `active [3]` | 활성화 성공 |

| Collision Monitor | `active [3]` | 활성화 성공 |

AMCL 초기화 후 지도상의 추정 위치는 시작 좌표에서 약 1.8cm 떨어져 있었습니다. 이는 **정지 상태의 위치추정 결과**이지 주행 후 도착 오차가 아닙니다.

현재 Nav2 활성화는 수동 복구를 통해 성공했습니다. Gazebo와 Robot 01 Stack을 완전히 다시 시작했을 때 자동으로 같은 상태가 되는지는 아직 검증되지 않았습니다.

## 4. 다른 대화에서 확인된 LAB 개발 이력

현재 프로젝트에서 확인 가능한 이전 대화 기록과 보관된 통합 구현 자료를 대조했습니다.

| 작업 단계 | 이전에 달성한 결과 | 현재 반영 여부 |
|---|---|---|
| 카페 환경·지도 | Gazebo 카페 및 LAB 지도 생성 | 현재 사용 중 |
| 테이블 경로계획 | 16/16 경로계획 성공 | 과거 시험 기록 |
| 픽업 경로계획 | 50개 경로점, 1.337m 경로 생성 | 과거 시험 기록 |
| 위치추정 복구 | AMCL 오차 1.5434m → 0.007m | 과거 시험 기록 |
| 서빙 관리 | 동적 정차점·적재·수령·복귀 상태 구현 | 현재 노드 실행 확인 |
| 사람 이벤트 연결 | 사람 이벤트 → Safety 연결 확인 | 실제 정지 미검증 |
| 속도 관리 | 속도 변경 명령 발행 성공 | 실측 미검증 |
| 회전·정체 감시 | 보호 프로그램 실행 및 회귀검사 | 실주행 효과 미검증 |
| 코드 회귀검사 | 18회 반복 검사 통과 | 실제 주행시험과 별개 |

여기서 과거의 AMCL 오차 0.007m와 이번 위치추정의 약 0.018m는 서로 다른 시점의 측정입니다.

과거 경로계획의 종점 오차 0m 역시 계획된 경로의 종점 일치 결과이지 로봇이 실제로 0m 오차로 정차했다는 뜻은 아닙니다.

## 5. 팀원 자율주행 작업물과 사용자 LAB 비교

이 부분은 가장 분명하게 구별해야 합니다.

| 비교 | 팀원 작업 기록·TEAM 소스 | 사용자 LAB |
|---|---|---|
| 목적 | 카페 서빙 로봇 | 동일 |
| 기반 | TEAM ROS 패키지·서빙 구성 | TEAM 원본을 바탕으로 LAB 확장 |
| 주행 | 팀원 문서에 서빙 완주 기록 | Nav2·Rotation Shim 적용 및 개별 주행 성공 이력 |
| 주방·테이블 | 팀원 설정 좌표와 도착 조건 | 동적 접근점·정밀 도착 판정 |
| HOME 복귀 | 팀원 문서에 전체 서빙 완료 기록 | 현재 LAB의 연속 서빙·복귀 미검증 |
| 정밀 도착 | 팀원 문서의 주방 도착 기준 15cm 사례 | LAB의 최종 물리적 위치 오차 목표 1mm |
| 사람 대응 | TEAM 안전 관련 구성 존재 | Semantic Safety와 사람 시뮬레이터 연결 확장 |
| Robot 02 | TEAM 다중 로봇 Launch 골격 | LAB 통합 구현 미완성 |

**팀원이 완료한 서빙과 사용자의 LAB 서빙은 같은 프로젝트의 작업이지만, 동일한 실행 결과는 아닙니다.**

따라서 팀원 문서에 서빙 완주가 있다고 해서 현재 LAB도 완주했다고 처리할 수 없습니다.

또한 팀원의 15cm 기준과 사용자의 1mm 목표는 적용 대상이 다르므로 단순 비교해서는 안 됩니다.

## 6. 실제 소스에서 확인한 중요한 구조

이번에 업로드된 TEAM·LAB ZIP의 파일 내용을 직접 확인한 결과입니다.

### A. Robot 01 통합 Launch

`~/team_robot_lab/integration/robot01_stack.launch.py`

이 파일은 새로운 Nav2를 구현한 것이 아니라 기존 Launch들을 묶은 상위 실행 파일입니다.

| 실행 단계 | 실제 코드 |
|---|---|
| 로봇 생성 또는 재사용 | `reuse_existing_robot` 분기 |
| 사람 시뮬레이터 | 시작 5초 후 실행 |
| 사람 이벤트 Bridge·Safety | 8초 후 실행 |
| 지도·AMCL | 10초 후 실행 |
| Nav2 | 16초 후 실행 |
| 초기 위치 전달 | **구현되지 않음** |
| 준비 완료 대기 | **시간 지연만 사용** |
| 서빙·속도·회전·정체 관리자 자동 생성 | **기존 프로세스 재사용 전제** |

즉, 이번에 발생했던 초기화 오류는 해당 통합 Launch의 설계와 일치합니다. 파일 자체에도 시작 지연 시간이 실제 ROS 준비 완료를 보장하지 않는다고 명시되어 있습니다.

또 하나 확인된 문제는 중복 노드 감지에 `ros2 node list --no-daemon`을 사용한다는 점입니다. 이번 실행 환경에서는 이 명령이 불완전한 목록을 반환했으므로, 그 검사를 절대적인 중복 방지 장치로 신뢰할 수 없습니다.

### B. Robot 02 실행 파일

두 파일의 차이가 명확합니다.

| 파일 | 실제 내용 |
|---|---|
| LAB `serving_robot_bringup/launch/multi_robot.launch.py` | **0바이트, 빈 파일** |
| TEAM `serving_robot_bringup/launch/multi_robot.launch.py` | 두 로봇의 운영 Launch를 호출하는 코드 존재 |

TEAM 다중 로봇 Launch에는 `robot02_model_ready`라는 실행 조건이 있습니다. 기본값은 `false`이며, 코드 주석에도 **Robot 02 모델과 TF를 별도로 준비해야 한다**고 명시되어 있습니다.

따라서 TEAM 파일이 존재한다는 사실만으로 Robot 02가 완성됐다고 판단할 수 없습니다.

또한 TEAM 파일은 Robot 01과 Robot 02의 운영 구성을 동시에 실행하는 방식이므로, 현재 실행 중인 Robot 01 Stack 위에 그대로 추가하면 Robot 01 관련 노드가 중복될 위험이 있습니다.

**Robot 02는 기존 Robot 01 Stack을 유지하면서 두 번째 로봇만 추가하는 독립 실행 구조가 필요합니다.**

### C. Safety 연결

업로드된 LAB 안전 Launch에는 속도 평활화, Semantic Safety, Collision Monitor가 정의되어 있습니다.

이번에 적용한 Lifecycle 패치로 속도 평활화와 Collision Monitor가 활성화된 것은 확인됐습니다. 그러나 업로드 당시의 원본 설정에는 속도 평활화의 출력이 Semantic Safety로 정확히 이어지는지 검토할 부분이 남아 있습니다.

따라서 **안전 관련 노드가 모두 Active라는 사실만으로 최종 속도 전달 경로가 정상이라고 승인할 수 없습니다.**

## 8. 지금부터 진행할 순서

원래 기획서와 현재 구현 상태를 함께 적용하면 다음 순서가 타당합니다.

<list marker="number" connector="solid" gap={2}>
  <list-item>
    **Robot 01 화면 주행 확인**

    이미 복구된 Nav2를 유지하면서 안전 속도 명령 경로를 확인하고, 기존 목적지 명령으로 짧은 주행을 실시합니다. 이번에 성공한 초기화 작업을 다시 반복할 필요는 없습니다.
  </list-item>
  <list-item>
    **Robot 01 서빙·안전 통합 확인**

    픽업 → 테이블 → 수령 → 복귀, 사람 앞 감속·정지·재계획, 실제 속도, 회전 및 도착 오차를 검증합니다. 여기서 실패한 기능만 수정합니다.
  </list-item>
  <list-item>
    **Robot 02 복제 구현**

    Robot 01 모델·센서·Nav2·Safety를 재사용하면서 Robot 02 전용 이름공간, TF, Odometry, LiDAR, 속도 명령, 초기 위치를 독립시킵니다. Robot 01의 정상 기능은 다시 개발하지 않습니다.
  </list-item>
  <list-item>
    **다중 로봇 협업 및 전체 서비스 연동**

    좁은 통로 교행·Zone 점유·교착 복구를 구현하고, 실제 팀원의 Fleet·Backend·Frontend 작업물과 연결합니다.
  </list-item>
  <list-item>
    **최종 시뮬레이션 시험과 기록**
