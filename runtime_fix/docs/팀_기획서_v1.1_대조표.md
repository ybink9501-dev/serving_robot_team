# 팀 시뮬레이션 담당 기획서 v1.1 — 구현/검증 대조

기준일: 2026-10-12. '제안'과 '팀 승인' 구분.

| v1.1 완료조건 | 실제 소스 | 검증 방법 | 2026-10-22 판정 |
|---|---|---|---|
| 2대 Gazebo 동일 월드 | `01_world.launch.py` + `02_robots.launch.py`, 로봇 2개 SDF | `tools/acceptance.py` | 소스 구현, 현장 미검증 |
| ROS Namespace/TF 분리 | 로봇별 Nav2 YAML, bridge, `odom_tf.py` | lifecycle, TF 실측 | 구성 구현, 현장 미검증 |
| 직진/좌우회전/정지 실측 | `metrics.py`, `trial.py` | Ground Truth vs odom, TF, cmd | 기록기 구현, 값 미측정 |
| Mapping 정적/Operation 동적 분리 | 정적 world + 별도 `sim_scenario.py` | 동적 객체 on/off | 구성 구현, 현장 미검증 |
| 1~8명·횡단·정지·재이동·가림 | 사람 SDF 물리 모델 + `sim_scenario.py` | Gazebo collision / sensor image | 시나리오 구현, 현장 미검증 |
| 고정·동적 장애물 | SDF collision, 이동 장애물 모델 | contact / Gazebo 실제 위치 | 시나리오 구현, 현장 미검증 |
| Zone 경합/교착 | `ZoneArbiter` + Fleet 거리 안전 | 동시 `trial.py` 2개 | 정책 구현, 동시 실행 미검증 |
| 센서 데이터 단절 | Safety stale sensor fail-closed | scan 발행 강제 중단 | 정책 구현, 고장 주입 미검증 |
| 명령/안전/odom/접촉 분리 | `metrics.py`, `contact_record.py` | CSV + JSONL | 기록기 구현, 측정 결과 미확보 |
| 정답 좌표와 인식 결과 분리 | `/cafe/people_ground_truth` vs `/cafe/people_detected` | 소스/토픽 확인 | 구조 검사 통과 |
| 팀 승인 수치 준수 | `policy.py`, Nav2 YAML | 원본 설계값 대조 | 구성 검사 통과, 팀 최종 승인 확인 필요 |
| 실패 재현과 인계 | 시나리오 CLI, 분석 도구, 결과 폴더 | 현장 반복 시나리오 | 도구 구현, 재현 로그 없음 |

**이 문서는 오프라인 구현 범위 및 현장 수용 기준을 기록하며, ROS/Gazebo 실주행 합격을 주장하지 않는다.** 팀 원본 소스에 대한 byte 비교는 원본 아카이브가 이 작업 환경에 없어서 수행되지 않았다.
